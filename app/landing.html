The premise

There is no way to ask an ATS who its customers are.

Every collection endpoint returns 401. There's no sitemap, no public customer directory, no list to download. You can only ask about one company at a time — and when you do, the answer is complete and free.

So the work starts by collecting candidate company names from eleven public datasets, then asking the live API about each one. A HEAD request costs nothing and downloads nothing, which makes verifying 7,951 guesses a two-and-a-half-minute job rather than a bandwidth problem.

Merging eleven sources instead of trusting the largest one yields 73% more companies. The added boards are smaller on average but their median is identical at 7 jobs each — they're real companies, just less famous ones, which is exactly where the less-contested postings are.

404 and “zero jobs” are different answers. A company between hiring rounds returns 200 with an empty list; conflating the two deletes real companies from the corpus.

One request returns one whole board GET api.ashbyhq.com/posting-api/job-board/<slug>
    ?includeCompensation=true

No pagination, no key, no scraping — the whole careers page in one response. includeCompensation must be exactly lowercase true: True also returns 200 and silently omits every salary.

How it works

Five stages. Each one re-runnable on its own.

Normalization is a pure function of what the sweep stored, so improving a city alias or a seniority rule costs a re-derive — never a re-sweep, and never a request to anyone's server.

The load-bearing idea

A blank field is not a no.

Every criterion returns one of three answers — match, no, or unknown — and your profile decides what happens to the third. Nothing is ever ruled out for failing to mention something.

Criterion Unknown Default Why
Salary62.8% include A silent floor is the most destructive thing a filter can do — six jobs in ten name no figure.
Seniority24.9% separate 232 jobs against 221 confirmed. Too many to drop, too many to mix in — so they get their own list.
Location15.9% exclude The one deliberate exception: a job with no parseable location isn't plausibly in your city.
Workplace1.1% include Small enough not to matter either way.
Employment type · date posted~0% include Effectively always stated.

Every one of these is a toggle in the app, with the affected share printed next to it. You are told what a setting costs you before you choose it.

Quick start

Four commands to a searchable corpus.

Requires Node 22.5 or newer, and nothing else — no API key, no account, no hosted service. The first refresh takes about three minutes, most of it verifying slugs; every one after that is under two.

Then it's a local page at :7799. The same search runs in the terminal with npm run find, and npm run schedule writes a launchd job or a GitHub Actions workflow — and installs neither until you ask.

$ npm install
$ npm run refresh # sync → verify → sweep → derive
$ npm test # 176, no db, no network
$ npm run serve # http://localhost:7799
